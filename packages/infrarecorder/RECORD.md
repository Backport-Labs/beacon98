# InfraRecorder - Beacon 98 package record

- Date checked: 2026-09-29
- Package: InfraRecorder (Christian Kindahl), CD/DVD burning
- Versions examined: 0.50 (2009-08-16, requested), 0.45 (2008-04-25, last with a non-Unicode "ANSI" build), 0.53 (2012-09-01, newest)
- License: 0.50 GNU GPL v3; 0.45 GNU GPL v2. Bundled cdrtools are CDDL/GPL/LGPL, bundled cygwin1.dll is GPL. The 0.50 logo graphics are CC BY-NC-ND 3.0 with an extra condition.
- Recommendation: **0.45 ANSI build** (`ir045_ansi.exe`). It runs on stock Windows 98/ME. **0.50 does not run on stock 98: it needs KernelEx.** List 0.50 only as a KernelEx alternative, if at all. List the package as `external` until the cdrtools and Cygwin sources are found (see License).

## Windows 9x support evidence

- **0.50 needs KernelEx.** I read the PE import table of `InfraRecorder.exe` 0.50 from `ir050_portable.zip` with a PowerShell parser (the program was not run):
  - It is a pure Unicode build that uses the wide-character (W) Windows functions directly, with no Microsoft Layer for Unicode (unicows.dll).
  - Its imports include USER32 `RegisterClassExW`, `CreateWindowExW`, `DefWindowProcW`, `CreateDialogParamW`, `DialogBoxParamW`, `GetMessageW` and `DispatchMessageW`. It also uses KERNEL32 `CreateFileW`, `CreateProcessW` and `GetFileAttributesExW`, COMCTL32 `PropertySheetW` and ADVAPI32 `Reg*W`.
  - On stock Windows 95/98/ME, most of these wide functions are stubs that fail. The program cannot create its windows without unicows or KernelEx.
  - The PE header says OS/subsystem version 4.0, so the loader accepts it. The failure would come at run time. (This is inference from the imports; not tested on 98.)
- The author's changelog says the same (whats_new.html in InfraRecorder.chm 0.50, decompiled with hh.exe). The entry for 0.41.0.0 reads: "Due to limitations in the Microsoft Windows 9x Unicode Layer, a non-unicode version of InfraRecorder is released separateley."
- SourceForge file lists (https://sourceforge.net/projects/infrarecorder/rss?path=/InfraRecorder/<ver>, opened) show which versions had an ANSI build:
  - 0.42.1, 0.44.1 and 0.45 have `*_ansi.exe` and `*_ansi.zip`.
  - 0.46, 0.46.1, 0.46.2, 0.50 and 0.53 ship only one 32-bit build (plus x64).
  - **0.45 is therefore the last ANSI build.**
- 0.50's help file, page system_requirements.html, says "Windows 98 with Internet Explorer 5.0 or newer." This page was not updated after the ANSI build was dropped, and the binary contradicts it.
- **0.45 ANSI runs on stock 98 (from its imports).** `InfraRecorder.exe` 0.45.0.0 from `ir045_ansi.zip` imports only ANSI API functions. Its only wide imports (`lstrlenW`, `lstrcmpW`, `LoadStringW`, `Get/SetWindowLongW`, `CallWindowProcW`, and the VC++ 2005 runtime's `GetEnvironmentStringsW`, `LCMapStringW`, `GetStringTypeW`, `WriteConsoleW`) exist on 9x or have fallbacks in the runtime. `irShell.dll`, `irExpress.exe` and `cdrtools\*` have OS/subsystem version 4.0.
- **Windows 95 is not supported by 0.45.** The VC++ 2005 runtime imports `InterlockedCompareExchange`, which Windows 95 does not have, and VC++ 2005 does not support 95. So Systems is 98, ME.
- Earlier changelog entries show that 9x was supported until then: 0.44 "Fixed a bug causing incompatibility with Windows 9x systems due to a function call to SHGetFolderPathA", and 0.44 "Fixed a bug causing InfraRecorder to crash on Windows 9x systems when changing folder in the explorer view".
- The bundled `cygwin1.dll` is version 1.5.25-cr-0x5f1 in both 0.45 and 0.50. The Cygwin 1.5 series still supports 9x; 1.7 dropped it.
- **0.53 is not usable on 98.** Its PE header has OS/subsystem version 5.1 (XP), and it is Unicode only.
- A web search snippet (not a primary source) says "InfraRecorder 0.50 works on Windows 98/ME with KernelEx 4.0", citing the retrosystemsrevival KernelEx app list. A PortableApps thread (https://portableapps.com/node/18986) returned 403 and was not read.

## Security

- NVD keyword "infrarecorder": 1 result, CVE-2018-25274. "InfraRecorder 0.53 contains a denial of service vulnerability that allows local attackers to crash the application by importing a maliciously crafted text file."
  - NVD lists only 0.53.
  - File-list import was added in 0.50 ("Added support for importing data from file lists like M3U"), so 0.50 may be affected. Unknown; not verified.
  - 0.45 has no such import feature, so it is probably not affected.
- NVD "cdrecord"/"cdrtools": CVE-2003-0289, CVE-2003-0655, CVE-2004-0806 and CVE-2005-0866. All concern setuid-root cdrecord/rscsi on Unix and do not apply to the Windows/Cygwin build on 9x.
- Summary: 0 applicable known problems for 0.45; 0 to 1 (a DoS, CVE-2018-25274) for 0.50. No `Warning:` is needed.

## Install behaviour

- Installer type: **NSIS** for both versions (the "Nullsoft"/NullsoftInst signature is in both exes). Silent: standard NSIS `/S`, optionally with `/D=<dir>` last.
- These facts are from `Setup/InfraRecorder.nsi` in ir045_src.zip; the 0.50 script is not in its source zip, so for 0.50 they are assumed the same but not verified:
  - Default folder `$PROGRAMFILES\InfraRecorder`, stored in HKCU `Software\InfraRecorder`.
  - The core section installs InfraRecorder.exe, irExpress.exe, irShell.dll, the codecs and cdrtools.
  - Add/Remove Programs: HKLM `...\Uninstall\InfraRecorder`, DisplayName **"InfraRecorder"**, UninstallString `$INSTDIR\uninstall.exe`.
  - Start Menu folder "InfraRecorder" with InfraExpress, InfraRecorder, Help and Uninstall. Desktop and Quick Launch shortcuts are in the default install type.
- **Add/Remove name: "InfraRecorder" (0.45 verified from the script; 0.50 unknown, probably the same).**
- The 0.45 installer contains both the ANSI and the Unicode script branches. `irsetup_ansi.exe` is built from the non-UNICODE branch (BinaryA files).
