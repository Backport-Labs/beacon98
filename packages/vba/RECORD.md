## License

- README-win.txt: "VisualBoyAdvance - a Gameboy and GameboyAdvance emulator, Copyright (C) 1999-2003 Forgotten, Copyright (C) 2004 Forgotten and the VBA development team. This program is free software; ... GNU General Public License ... either version 2 of the License, or (at your option) any later version." COPYING in the zip is the GPL 2 text.
- LICENSE.TXT here: the README-win.txt license section and COPYING.
- GPL allows redistributing the unmodified binary with the complete corresponding source. **Problem:** the Windows build statically links libraries that are only present as prebuilt .lib files in the source archive (`win32/lib/win32/`): zlib 1.1.3, libpng 1.2.0, IJG libjpeg 6b, CxImage (version unknown) and Microsoft's **d3dx8.lib** (GBA.dsp: `ADD LINK32 d3dx8.lib ...`; the exe contains D3DX8 code, e.g. the string "D3DXPSGP"). zlib, libpng, libjpeg and CxImage are permissive and their sources could be added. D3DX8 is proprietary Microsoft SDK code, so the "complete corresponding source" can never be offered for this binary. Whether it counts under GPL 2's system-library exception is arguable (it was not part of Windows; it came with the DirectX SDK).
- Following the VLC precedent in CATALOG.TXT, the draft lists VBA as `external` from SourceForge. Alternative if Backport Labs accepts the system-library reading: host it with the source below plus zlib-1.1.3, libpng-1.2.0, jpeg-6b and CxImage sources (not downloaded). Second alternative: host the SDL command-line build (clean, but awkward to use).

## ROMs and other bundled data

Zip listing (.NET ZipFile): `COPYING`, `NEWS`, `README-win.txt`, `VisualBoyAdvance.exe`, no folders. **No ROMs and no BIOS image.** The GBA BIOS is not included; VBA emulates BIOS calls in its own code (src/bios.cpp, GPL, Forgotten) and only loads a real BIOS if the user supplies one. Nothing questionable. The SDL build zip likewise has no ROMs.

## Security

- NVD keyword search "visualboyadvance" (API 2.0, 2026-09-29): 0 results. No project advisories (project inactive since 2004). Web search for exploits could not be done (search budget exhausted), so public exploits outside NVD were not checked.
- Bundled libraries: zlib 1.1.3 has CVE-2002-0059 (double free in inflate; VBA inflates zipped ROMs with it, src/unzip.cpp) and the later zlib CVEs for pre-1.2.x code; libpng 1.2.0 and libjpeg 6b have many CVEs (e.g. libpng CVE-2004-0597, a buffer overflow in png_handle_tRNS). The Windows build reads PNG/JPEG skins through CxImage (NEWS 1.7.2: "added JPEG and PNG support for skins").
- Summary: 0 CVEs for VBA itself; about the worst reachable issue is zlib CVE-2002-0059 (crafted zipped ROM) and libpng CVE-2004-0597 (crafted PNG skin). A short Warning is proposed.

## Install behaviour

- Plain zip with no folders: COPYING, NEWS, README-win.txt, VisualBoyAdvance.exe (about 1,773 KB unpacked).
- Beacon: `unzip {dir}` (nothing to strip), shortcut to `{dir}\VisualBoyAdvance.exe`, uninstall `files`. VBA writes vba.ini and save/battery files into its own folder by default, which Beacon does not remove.
- No installer, no Add/Remove Programs entry.
