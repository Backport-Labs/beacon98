# DOSBox 0.74-3 - Beacon 98 package record

- Date checked: 2026-09-29
- Package: DOSBox (The DOSBox Team), id `dosbox`
- Version: 0.74-3 (2019-06-26), the last release of DOSBox; there is no 0.75.
- License: GNU GPL 2.0 or later. Bundled SDL.dll (SDL 1.2.13, patched) and SDL_net.dll are GNU LGPL.
- Recommendation: 0.74-3. It is a security release of 0.74; 0.74, 0.74-2 and 0.74-3 are built the same way for Windows (same SDL.dll, same NSIS 2.46 installer, essentially the same imports), and 0.74-3 fixes CVE-2019-7165 and CVE-2019-12594. Nothing found suggests 0.74-3 lost 9x support.

## Windows 9x support evidence

The DOSBox project does not publish system requirements, and none of its pages or documents states which Windows versions the host must run. So the answer rests on the binaries:

- Official statements: dosbox.com news for 0.74-3 (opened): "A security release for DOSBox 0.74" ... "The game compatibility should be identical to 0.74 and 0.74-2." NEWS.txt in the installer says the same and lists no platform change for Windows except "Fix auto/max cycles algorithm on Windows 7" (0.74-2). README.txt still documents 9x-era features, e.g. "To enable low-level aspi-support (win98 with aspi-layer installed)".
- Import tables, read with a small PE parser on files extracted with the host's 7-Zip (nothing was run):
  - DOSBox.exe of 0.74, 0.74-2 and 0.74-3: PE subsystem 4.0. Its imports from KERNEL32, USER32, ADVAPI32, SHELL32, WINMM, WS2_32, OPENGL32 and msvcrt.dll are all functions that exist in Windows 98. The import lists of 0.74 and 0.74-3 differ only in two SDL and two OpenGL functions (SDL_GL_GetProcAddress, SDL_GetVideoInfo added; glEnableClientState, wglGetProcAddress dropped). 55 KERNEL32 imports in both 0.74-2 and 0.74-3.
  - SDL.dll (1.2.13.0) and SDL_net.dll are byte-identical in 0.74, 0.74-2 and 0.74-3 (SHA-256 of SDL.dll starts 69037ebc43755296 in all three). Only classic Win32 functions.
  - Installer: NSIS 2.46 ("Nullsoft Install System v2.46" in the manifest), subsystem 4.0; NSIS 2.x supports Windows 95 and later.
  - Exception: `Video Codec\zmbv.dll` of 0.74-3 (rebuilt with MinGW in 2019, 215,566 bytes) imports GetTickCount64 and AddVectoredExceptionHandler, which Windows 98 does not have, so the ZMBV video codec of 0.74-3 will not load on 98/ME. 0.74's zmbv.dll (MSVC, 94,208 bytes) imports only 9x-era functions. This codec is only needed to play back videos recorded with DOSBox in other players; the installer copies it but does not install it (the user right-clicks zmbv.inf). DOSBox itself records without it.
- Community: a VOGONS thread "DOSBOX on WIN98SE" (search snippet only, not opened) says DOSBox works on 98SE; it predates 0.74. Not tested here (no VM interaction).
- Windows 98 / ME: expected to work (imports all present). Not tested.
- Windows 95: needs more than stock 95. DOSBox.exe imports SHELL32!SHGetSpecialFolderPathA (present only from shell32 4.71, i.e. Windows 98 or 95 with the IE 4 Desktop Update), WS2_32.DLL (Winsock 2 update on 95) and OPENGL32.DLL (not in the first 95 release; OSR2 status not verified). The import requirements are from the binary; the shell32 version fact is from memory, not a page opened. Listed as 98 and ME only.
- KernelEx: not needed.

## Security

- NVD keyword search "dosbox" (API 2.0): 3 CVEs. CVE-2007-6328 (mount gives host filesystem access, <=0.72, disputed as by design), CVE-2019-7165 (bat-file line buffer overflow, 0.74-2, CVSS 9.8) and CVE-2019-12594 (access control, /proc, 0.74-2, CVSS 9.8). 0.74-3's own release notes say it fixes the two 2019 CVEs. None applies to 0.74-3.
- By design, a program running inside DOSBox can read and write every host folder that is mounted. The project advises: "It's recommended to use config -securemode when dealing with untrusted files."
- Bundled SDL 1.2.13: NVD lists 14 CVEs for SDL 1.2.x (e.g. CVE-2019-7577 SDL_LoadWAV over-read, CVE-2019-7637 SDL_FillRect overflow, CVE-2019-13616 BlitNtoN over-read, CVE-2022-34568 X11 only). Most are in the WAV/BMP loaders; DOSBox.exe does not import SDL_LoadWAV or SDL_LoadBMP, so reachability is doubtful but was not proven either way. SDL_FillRect/blit bugs need crafted surface parameters, not a user file.
- libpng 1.2.8 in DOSBox.exe has many CVEs in its PNG reader; DOSBox only writes PNG screenshots. Not assessed further.
- Summary: 0 known CVEs in DOSBox 0.74-3 itself; the worst previously known (CVE-2019-7165, fixed in this version). No Warning proposed.

## Install behaviour

- Installer type: NSIS 2.46 (7-Zip: Type Nsis, SubType NSIS-2, LZMA solid).
- Silent install: standard NSIS `/S` (and `/D=` last). Not documented by DOSBox; a third-party packaging note (appdeploynews.com, opened) uses `DOSBox0.74-3-win32-installer.exe /S` and `"...\DOSBox-0.74-3\uninstall.exe" /S`.
- Default folder: `$PROGRAMFILES\DOSBox-0.74-3` (string in the decompressed NSIS header; winget manifest: DefaultInstallLocation `%ProgramFiles(x86)%\DOSBox-0.74-3`).
- Add/Remove Programs: apparently NOT registered. The decompressed NSIS header (read with the host's 7-Zip LZMA decoder, not run) contains no `...\CurrentVersion\Uninstall` key string; the only registry path is `SOFTWARE\Microsoft\Windows NT\CurrentVersion`. The installer writes `uninstall.exe` in the program folder and a Start Menu shortcut `DOSBox-0.74-3\Extras\Uninstall.lnk`. Display name: none (unknown if any). This is an inference from the script strings, not a test.
- Start Menu folder `DOSBox-0.74-3` with DOSBox 0.74-3, Manual, Extras (noconsole, Uninstall, Screenshots & Recordings, Video\Install movie codec), Options (Options, Reset Options, Reset KeyMapper); optional desktop shortcut "DOSBox 0.74-3".
- Configuration: DOSBox creates `dosbox-0.74-3.conf` on first start in a per-user folder obtained with SHGetSpecialFolderPathA. Exact location on 98 not verified.
- Beacon: the catalog format has no uninstall kind that runs a program's own uninstaller without an Add/Remove Programs entry. `Uninstall: registry` will not work. Options: add an uninstall kind such as `exe {dir}\uninstall.exe /S` to FORMAT.md, or accept `files` (which would leave the NSIS-installed files). Needs a decision.
