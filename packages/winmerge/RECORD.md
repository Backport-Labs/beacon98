# WinMerge 2.12.4 - Beacon 98 record

- Date checked: 2026-09-29
- Package: WinMerge (Thingamahoochie Software / WinMerge developers)
- Version: 2.12.4 (stable, 2009-06-09, r6833)
- License: GNU GPL version 2 or later
- Recommendation: 2.12.4. The project's download page names it the last version for 95/98/ME/NT; 2.14.0 is the last for Windows 2000; current 2.16.x needs XP SP3 or later.

## Windows 9x support evidence

- https://winmerge.org/downloads/ (opened 2026-09-29), "Other Versions":
  "WinMerge 2.12.4 for Windows 95/98/ME/NT - WinMerge version 2.12.4 was the last version to ship with Microsoft Visual C++ 2005 runtimes that support Windows 95/98/ME/NT. It was also the last version to ship with an ANSI version of WinMerge."
  and "WinMerge 2.14.0 for Windows 2000 ... last version to ship with Microsoft Visual C++ 2008 runtimes that support Windows 2000."
  Current requirements on the same page: "32-bit installer: Microsoft Windows XP SP3 or newer".
- Installer script Installer/InnoSetup/WinMerge.iss in WinMerge-2.12.4-src.zip has separate 9x branches: `WinMerge.exe` (ANSI build) with `OnlyBelowVersion: 0, 4` (installed only on 95/98/ME), `WinMergeU.exe` with `MinVersion: 0, 4` (NT only), and likewise ShellExtension.dll / ShellExtensionU.dll, heksedit.dll / hekseditU.dll, mfc71.dll / mfc71u.dll.
- Discrepancy: the web page says "Visual C++ 2005 runtimes", but the 2.12.4 installer script ships the Visual C++ 2003 (7.1) runtimes mfc71.dll, msvcr71.dll, msvcp71.dll (Installer/Runtimes in the source archive). This does not change the 9x support.
- Windows 95 and ME: named on the download page. The source archive has Installer/Runtimes/Docs/Comctl32.DLL.mht, which suggests 95 may need a newer comctl32 (from IE); not verified. No KernelEx needed. Not tested in a VM.

## Security

- NVD API 2.0: CVE keyword search "WinMerge" returns 0; cpeName queries for cpe:2.3:a:winmerge:winmerge:2.12.4 and 2.0 return 0 (NVD does list 33 WinMerge CPEs, 1.7.1 to 2.19.10 beta). OpenCVE (app.opencve.io, vendor winmerge): "No CVE found".
- Snyk lists FreeImage CVEs (e.g. CVE-2021-40262, CVE-2023-47995, CVE-2023-47997) under "WinMerge/freeimage" (search snippet only). 2.12.4 has no FreeImage (not in Externals, not in the installer script), so they do not apply.
- Non-CVE issue: SourceForge bug #2182 "SECURITY: 2.14.0 Installer vulnerable to DLL Hijacking" (dwmapi.dll, search snippet only). 2.12.4 uses the same generation of Inno Setup (5.2.3); the attack needs a planted DLL next to the installer and matters little on 9x.
- Known CVEs affecting 2.12.4: 0. No `Warning:` in the entry.

## Install behaviour

- Installer type: Inno Setup 5.2.3 (version resource and setup-data signature); the script WinMerge.iss is in the source archive.
- Silent install: standard Inno `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` (Beacon `inno`). The WinMerge documentation was not checked for its own statement; the script has no [Code] prompts found by a search for MsgBox. [Run] entries are `skipifsilent`.
- Default folder: `{pf}\WinMerge` (DefaultDirName); Start Menu group "WinMerge".
- Uninstaller: yes (Inno). No AppId or UninstallDisplayName in the script, so Inno uses AppName for the key (`WinMerge_is1`) and AppVerName for the display name: **"WinMerge 2.12.4"** (derived from the script and Inno's defaults, not observed on a system).
- Side effects (from the script, default tasks): installs mfc71.dll, msvcr71.dll, msvcp71.dll into `{sys}` as shared files that are never uninstalled; registers ShellExtension.dll (Explorer context menu, task checked by default); quick-launch icon (checked by default); PATH addition is unchecked by default (ChangesEnvironment=true; on 9x modpath edits AUTOEXEC.BAT); creates HKCU/HKLM `Software\Thingamahoochie\WinMerge`; ChangesAssociations=true (.WinMerge project files).
