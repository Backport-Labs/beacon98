# PrBoom 2.5.0 - Beacon 98 package record

- Date checked: 2026-09-29
- Package: PrBoom (Doom source port; Florian Schulze, Colin Phipps, Neil Stevens, Andrey Budko and others), id `prboom`
- Version: 2.5.0 (2008-11-09), the last release of PrBoom. Its successor PrBoom+ is a separate project and was not assessed here.
- License: GNU GPL 2.0 or later. Bundled SDL.dll, SDL_mixer.dll, SDL_net.dll: GNU LGPL 2.1; smpeg.dll: GNU Library GPL 2.
- Game data: none from id Software. The zip holds only PrBoom's own `prboom.wad` (a PWAD with engine resources, GPL). Freedoom (package `freedoom`) supplies free IWADs.
- Recommendation: 2.5.0, Systems 98 and ME.

## Windows 9x support evidence

- https://prboom.sourceforge.net/windows.html (opened): "PrBoom should work with Windows 9x, Windows NT4.0 and Windows 2000 or above." The page says the SDL, SDL_mixer and SDL_net DLLs are bundled.
- https://prboom.sourceforge.net/ (opened): "Version 2.5.0 released", 9th November 2008; newest release on the page. NEWS (2.4.x era) says "Windows: Converted project files to free Visual Studio 2005 Express Edition".
- Import tables (PE parser on files extracted to a temp folder; nothing was run):
  - prboom.exe, glboom.exe, prboom_server.exe: linker 8.0 (Visual C++ 2005), OS/subsystem 4.0, C runtime linked statically (no msvcr80.dll needed). Imports only KERNEL32, USER32, GDI32, SDL*, and for glboom OPENGL32/GLU32. All present on Windows 98.
  - Two imports need a closer look: `IsDebuggerPresent` (from the VS2005 CRT; exists from Windows 98, not in Windows 95 - from memory) and `SetProcessAffinityMask`. PrBoom calls the latter at start-up (src/SDL/i_system.c, I_SetAffinityMask) and on failure only logs "failed to set process affinity mask". Windows 9x kernel32 is expected to export it as a stub that fails; supporting evidence: KernelEx 4.5.2's source (which adds missing kernel32 exports) does not implement it. Not proven; the VM test must confirm prboom.exe starts.
  - SDL.dll, SDL_mixer.dll, SDL_net.dll, smpeg.dll: MinGW gcc 3.4.5, OS 4.0, import only classic Win32 APIs and msvcrt.dll/WSOCK32/WINMM.
- Windows 95: not listed. The VS2005 runtime does not support Windows 95 and imports IsDebuggerPresent.
- Windows ME: same binaries as 98; expected to work, not tested.
- KernelEx: not needed.

## Security

- NVD keyword "prboom" (API 2.0): 1 CVE. CVE-2019-20797 (CVSS 3.1 7.5): buffer overflows in the UDP packet handling of PrBoom+ 2.5.1.5 (ChecksumPacket, I_SendPacket, I_SendPacketTo in src/SDL/i_network.c; https://logicaltrust.net/blog/2019/10/prboom1.html, opened). NVD lists only prboom-plus, but PrBoom 2.5.0's i_network.c has the identical functions (checked in the 2.5.0 source), so 2.5.0 is affected. Reachable only in client/server network games (prboom_server.exe or -net).
- NVD "smpeg", "SDL_mixer", "freedoom": 0 results. SDL 1.2.x: about 14 CVEs, mostly in SDL_LoadWAV/BMP and blitters (see the dosbox record); PrBoom does not import the loaders.
- libmikmod: 7 CVEs (e.g. CVE-2010-2546, IT loader heap overflow, CVSS2 9.3). NVD ranges start at 3.1.9 or later; SDL_mixer 1.2.8 contains MikMod 3.1.8, so whether they apply is unknown. A music lump in a malicious add-on WAD that is a MOD/IT file would reach MikMod.
- General: Doom engines of this age parse level and graphics data with few checks; a malicious add-on WAD can likely crash the engine. No CVEs are recorded for that.
- Summary: 1 known CVE (CVE-2019-20797, network games only). Proposed Warning about network games.

## Install behaviour

- Type: plain zip, no installer, no registry entries. PrBoom writes prboom.cfg and saved games into the folder of the exe (I_DoomExeDir returns argv[0]'s folder on Win32; savegame path = I_DoomExeDir unless DOOMSAVEDIR or -save is given).
- Layout: one top folder `prboom-2.5.0-win32/`; Beacon should `unzip {dir} strip 1`.
- IWAD search (src/d_main.c FindIWADFile and src/SDL/i_system.c I_FindFile): without -iwad it tries, in order, doom2f.wad, doom2.wad, plutonia.wad, tnt.wad, doom.wad, doom1.wad, doomu.wad, freedoom.wad in: the current directory, %DOOMWADDIR%, %HOME%\doom, %HOME%, the exe folder. `-iwad <name or full path>` is looked up first as given, so an absolute path works. The names freedoom1.wad and freedoom2.wad are NOT recognised automatically; that is why the freedoom package uses -iwad.
- Shortcut: `PrBoom | {dir}\prboom.exe |`. Without an IWAD PrBoom stops with "IdentifyVersion: IWAD not found"; the Notice explains this. glboom.exe (OpenGL) is left without a shortcut.
- Music: SDL_mixer 1.2.8 uses TiMidity if a timidity.cfg is found, otherwise Windows' own MIDI output (music.c: native_midi_ok = !timidity_ok). README.txt still says patch sets are needed; with Windows MIDI they should not be. Not tested.
- Uninstall: `files`. prboom.cfg and saved games created later by the program are not in Beacon's record and stay behind.
