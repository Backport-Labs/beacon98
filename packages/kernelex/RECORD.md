## Security

- NVD API 2.0 keyword search "KernelEx" (2026-09-29): 0 CVEs; CPE search "kernelex": 0 CPEs. No project advisories exist.
- Known issues by design, not CVEs:
  - It changes how Windows works for every program: a VxD (VKrnlEx.vxd, loaded as a static VxD) patches KERNEL32 in memory before the shell starts, KernelEx.dll is loaded as an MPR service, and it adds API extensions to all programs by default. Faults can make Windows unstable or unbootable; a backup (or at least a system file backup) before installing is advisable.
  - Its purpose is to let Windows 2000/XP programs run on 98/ME, which have no user/kernel protection; programs run this way get no protection they would have on NT.
  - The installer's MSLU section can download http://download.microsoft.com/.../unicows.exe over plain HTTP with NSISdl and run it without checking it (only when UNICOWS.DLL 1.1.3790.0 is missing and the user agrees). In silent mode it answers No (`/SD IDNO`) and aborts instead, so Beacon's install never downloads it. (The URL currently answers HTTP 302.)
- Summary: 0 known CVEs. The Warning covers the system change, the backup advice and the lack of any security review.

## Install behaviour

- Installer type: NSIS 2 (7-Zip reports Type = Nsis, SubType = NSIS-2, LZMA solid; the "Nullsoft" signature is in the exe; script KernelEx.nsi in the source).
- Silent install: not documented by the project; standard NSIS `/S` (and `/D=` for the folder). Behaviour in silent mode, from KernelEx.nsi:
  - .onInit aborts on anything but 98/ME, if an earlier installation is waiting for a restart (RunServicesOnce KexNeedsReboot), if a pre-4.0 KernelEx/KUP is present ("Please uninstall it"), or on a downgrade from a newer KernelEx. Those MessageBoxes have no /SD, so they still appear in silent mode.
  - MSLU check: requires $SYSDIR\unicows.dll with version exactly 1.1.3790.0. If missing or a different version, silent mode aborts (the install fails). Hence `Requires: file {sys}\UNICOWS.DLL`; note that the version must be 1.1.3790.0, which the Requires check cannot test.
  - The "Default configuration" custom page is skipped in silent mode, so DisableExtensions is not written; core/apiconfmgr.cpp only disables extensions when it is 1, so extensions are enabled for all programs (the installer's recommended choice).
  - Sets the reboot flag. A silent NSIS install does not restart by itself; KernelEx works only after a restart, so the entry has a Notice.
- Default folder: `$WINDIR\KernelEx` (e.g. C:\WINDOWS\KernelEx), stored in HKLM Software\KernelEx InstallDir. Not {pf}.
- Writes: KernelEx.dll, kexbases.dll, kexbasen.dll, sheet.dll and kexCOM.dll (registered), VKrnlEx.vxd, msimg32/pdh/psapi/uxtheme/wtsapi32/userenv.dll into its own folder (as KernelEx KnownDLLs, not in SYSTEM), core.ini, License.txt, Release Notes.txt, verify.exe, Uninstall.exe; $WINDIR\AppPatch\Custom\KernelEx.sdb plus AppCompatFlags entries (Office 2003/2007 converters, Google Earth, Acrobat Reader 7 MSI fixes); settings.reg imported (per-program settings); HKLM ...\Services\VxD\VKRNLEX StaticVxD; HKLM ...\Control\MPRServices\KernelEx; Run key "KexVerify" = verify.exe; Start Menu folder "KernelEx" (Release Notes, Verify Installation, Home Page, Wiki, Uninstall). If an older KernelEx left a patched KERNEL32.DLL with a backup, it restores the original.
- Uninstaller: yes. HKLM Software\Microsoft\Windows\CurrentVersion\Uninstall\KernelEx, DisplayName "KernelEx 4.5.2" (`"KernelEx ${VERSION}"`, VERSION 4.5.2 for the release build), UninstallString "$INSTDIR\uninstall.exe". The uninstaller asks "Do you want to preserve custom settings?" with no /SD default, so it is not fully silent, and it needs a restart.
- Installed size: about 480 KB of payload (7-Zip listing, excluding the NSIS plugins) plus the uninstaller; 500 KB used in the entry as an estimate.
