# Wings 3D 1.0 - Beacon 98 package record

- Date checked: 2026-09-29
- Package: Wings 3D (Bjorn Gustavsson, Dan Gudmundsson, Richard Jones and others), id `wings3d`
- Version: 1.0 (Windows installer built 2009-05-17)
- License: Wings 3D license.terms (BSD/Tcl-style permissive), plus bundled Erlang/OTP R13B (Erlang Public License 1.1), ESDL 1.0 (permissive), SDL 1.2.13 (LGPL 2.1), an FBX plug-in linked with the proprietary Autodesk FBX SDK, and the Microsoft VC++ 2005 SP1 redistributable
- Systems: 98, ME with KernelEx. Not 95 (KernelEx does not support 95).
- Recommendation: 1.0 with KernelEx, as reported by two lists. 1.0.1 and 1.0.2 exist on SourceForge too, but no one reports them with KernelEx. For stock 98 without KernelEx, 0.98.36 is the candidate (see below). It is a separate package decision and has not been verified here.

## Windows 9x / KernelEx evidence

- MSFN "KernelEx Apps Compatibility List (New)", https://msfn.org/board/topic/152471-kernelex-apps-compatibility-list-new/ (opened; first post dated 2011-07-19). The entry "Wings3D 1.0" (linking http://www.wings3d.com) is under "What is working with KernelEx". **No KernelEx version or compatibility mode is given.**
- Operating System Revival, "List of Working Windows 98/ME KernelEx Applications", https://retrosystemsrevival.blogspot.com/p/list-of-working-windows-98me-kernelex.html (opened). The entry "Wings3D 1.0" is under Digital Art Software. **No KernelEx version or mode is given.**
- Static import check of the 1.0 binaries (read with a PE header parser; nothing was executed):
  - `bin\beam.dll` is the Erlang emulator (the "5.7.1" and "R13B" strings mean ERTS 5.7.1 = Erlang/OTP R13B; the files are `lib\kernel-2.13.1`). It links MSVCR80.dll. It imports `SetFilePointerEx` (Windows 2000 and later) and `TryEnterCriticalSection` (NT only). It also imports Unicode window functions (`CreateWindowExW`, `RegisterClassExW`, `DialogBoxParamW`, `GetMessageW` and others), which Windows 98 only stubs out. So stock 98 cannot run it, and KernelEx is needed. This matches the two reports.
  - `wings_fbx_win32.dll` (the FBX plug-in) imports `CreateFileW`, `FindFirstFileW` and other W file functions.
- Secondary: Wikibooks "Wings 3D/User Manual/Installation" (https://en.wikibooks.org/wiki/Wings_3D/User_Manual/Installation, opened) says "OpenGL and Windows 2000 or higher are required in order to run Wings 0.99." No statement from the Wings authors about 9x was found in NOTES, README or BUILD.win32 of the 1.0 source.

### Older version without KernelEx (not verified by a run)

- Wings 0.98.36 (last 0.98.x; https://downloads.sourceforge.net/project/wings/wings/0.98.36/wings-0.98.36.exe, MD5 a0c4166888ab4e844aa1b94d7bd7afe1, which matches the SourceForge listing). I downloaded it to a temp folder only, to inspect it. It bundles Erlang ERTS 5.5.2 (R11B, binaries dated 2006-11-22). It has no vcredist. Its `beam.dll`, `erlexec.dll`, `werl.exe`, `inet_gethost.exe` and `Wings3D.exe` link plain MSVCRT.dll. They import no W window APIs, no `SetFilePointerEx` and no `TryEnterCriticalSection`. So it is a plausible stock-98 build.
- 1.0 NOTES, entry "0.99.00a": "The installer for Windows will now install the run-time library for Microsoft C if it is not already installed." This is where the switch to the VC2005-built Erlang (R12B) happens. The "0.99.02" entry says "Now using Erlang/OTP R12B-1".
- No primary statement was found that 0.98.36 runs on 98. The Erlang/OTP R11B-2, R12B-0 and R13B readmes (erlang.org/download, opened) say nothing about 9x either way. 0.98.36 must be tested in the VM before it is offered as a no-KernelEx alternative. If it works, it may be preferable for users without KernelEx.

## Security

- NVD keyword "wings3d": 1 result. CVE-2026-39020 (CVSS 5.5): a crafted Wavefront OBJ file causes denial of service in Wings3D 2.4.1. Whether 1.0 is affected is unknown.
- Bundled SDL 1.2.13 is inside the NVD range of CVE-2019-7635 (heap over-read in Blit1to4, SDL through 1.2.15, CVSS 8.1). The other 2019 SDL 1.2 CVEs (CVE-2019-7572 to -7578, -7636 to -7638) are mostly in WAV/audio and BMP handling; ESDL removes sdl_audio. Whether Wings reaches those paths was not checked.
- Erlang/OTP R13B: most OTP CVEs are in ssl, ssh and inets, which Wings does not bundle (only erts/kernel/stdlib). The ERTS-level CVEs were not enumerated. The NVD API rate-limited the queries.
- Summary: 0 CVEs confirmed for Wings 1.0 itself, 1 possible (CVE-2026-39020), and the bundled SDL 1.2.13 falls under CVE-2019-7635 and related CVEs. All need the user to open a crafted file.

## Install behaviour

- Installer type: NSIS 2 (7-Zip reports "Nsis, NSIS-2"). The script is `win32/wings.nsi` in the source (read).
- Silent switch: standard NSIS `/S` (the Wings docs say nothing about it).
- **Caveat:** the section "Microsoft redistributable libraries" is selected when msvcr80.dll is not found in SYSTEM or WinSxS, which is always the case on 98. It runs `ExecWait '"$INSTDIR\vcredist_x86.exe"'` with no switches. That IExpress package runs `msiexec /i vcredist.msi` with full UI, so even with `/S` the user sees and must click through the VC++ 2005 setup. vcredist.msi has Summary "Page Count" 200, so it needs **Windows Installer 2.0**, which stock 98 SE does not have.
- The installer also runs `$INSTDIR\Wings3D.exe --install` (sets up the Erlang run-time).
- Default folder: `$PROGRAMFILES\wings3d_1.0`. It is remembered in HKLM `SOFTWARE\Wings 3D\1.0`.
- Uninstaller: `$INSTDIR\Uninstall.exe`, registered at HKLM (or HKCU as a fallback) `Software\Microsoft\Windows\CurrentVersion\Uninstall\Wings 3D 1.0`, with DisplayName **"Wings 3D 1.0"**, NoModify and NoRepair.
- Side effects: a Start Menu folder "Wings 3D 1.0" (All Users), `.wings` association (section "Make Default", on by default), optional Desktop/QuickLaunch shortcuts (off by default), plugins.lnk in the install folder. The uninstaller leaves the VC++ 2005 run-time installed.
