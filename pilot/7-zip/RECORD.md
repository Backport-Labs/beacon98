# 7-Zip 9.20 - Beacon 98 pilot record

- Date checked: 2026-09-28
- Package: 7-Zip (Igor Pavlov)
- Version: 9.20 (stable, 2010-11-18)
- License: GNU LGPL 2.1 or later, plus unRAR restriction for the RAR decoder in 7z.dll
- Recommendation: 9.20. Newer builds 9.21 beta to 9.30 alpha were never stated to drop 9x, but they are beta/alpha. 9.32 alpha states in writing that it does not work on 95/98/ME. 9.20 is the last stable release, and its own readme lists 95/98/ME.

## Windows 9x support evidence

- https://www.7-zip.org/history.txt (verified by downloading), entry "9.32 alpha 2013-12-01":
  "Minimum supported system now is Windows 2000. 7-Zip doesn't work on Windows 95/98/ME."
  The versions before it are 9.30 alpha (2012-10-26), 9.25 alpha, 9.23 alpha, 9.22 beta, 9.21 beta and 9.20 (stable, 2010-11-18).
- readme.txt inside 7z920.exe (opened after extracting it with the host's 7-Zip; the installer was not run):
  "7-Zip is a file archiver for Windows 95/98/ME/NT/2000/2003/2008/XP/Vista/7."
- readme.txt inside the official 7za920.zip (command-line build, https://www.7-zip.org/a/7za920.zip, opened):
  "7za.exe can work in Windows 95/98/ME/NT/2000/2003/2008/XP/Vista/7."
- Windows 95: included by name in both statements above. History shows 9x-specific fixes in the past, e.g. "4.32: Bug was fixed: 7-Zip 4.31 didn't work in Windows 95". Not tested on 95 here.
- 9.30 alpha (latest pre-9.32 build) was NOT downloaded or checked. The SourceForge RSS for /7-Zip/9.30 returned 404.

## Security

Sources: NVD API 2.0 (cpeName cpe:2.3:a:7-zip:7-zip:9.20 gives 19 matches, plus a keyword search) and history.txt. I checked 9.20's source tree to see which handler each CVE depends on.

Affect 9.20 (NVD range covers 9.20, and the vulnerable handler is present in 9.20 source):
- CVE-2016-2334: HFS+ zlib heap overflow (before 16.00), CVSS2 9.3.
- CVE-2016-2335: UDF out-of-bounds read / code execution (NVD names 9.20 explicitly).
- CVE-2016-7804: untrusted DLL search path (DLL hijack) in the installer/SFX (16.02 and earlier).
- CVE-2017-17969: Shrink (ZIP) decoder heap overflow (before 18.00).
- CVE-2018-5996: RAR3/PPMd exception handling, memory corruption (before 18.00).
- CVE-2018-10115: RAR decoder uninitialized memory, RCE (18.03 and before).
- CVE-2023-31102: Ppmd7 integer underflow (before 23.00).
- CVE-2023-52168 / CVE-2023-52169: NTFS handler heap overflow / out-of-bounds read (before 24.01).
- CVE-2025-53817: Compound (COM) handler null dereference, DoS (before 25.0).
- CVE-2026-48095: NTFS compressed-stream heap overflow, possible RCE (26.00 and prior), CVSS 8.8. The NTFS handler (NtfsHandler.cpp) is present in 9.20.
- CVE-2026-14266: XZ decompression heap overflow, RCE (before 26.02), CVSS 7.8. 9.20 has an XZ handler.
- CVE-2026-48102: UDF File Identifier out-of-bounds read (9.11 to 26.00).
- CVE-2026-48104: SquashFS uninitialized heap read (9.18 to 26.00).

NVD CPE match, but not relevant on Windows 98 or needs checking:
- CVE-2018-10172: large-pages privilege (LsaAddAccountRights). NT-only API, so it does not apply on 9x.
- CVE-2022-29072: Help > Contents drag-and-drop (disputed by the vendor).
- CVE-2024-11477: Zstandard. 9.20 has no zstd support, so not affected.
- CVE-2025-53816: RAR5. 9.20 has no RAR5 support, so not affected.
- CVE-2025-0411, CVE-2026-58052: Mark-of-the-Web bypass. 9.20 never propagated MotW and 9x has no ADS/MotW, so not applicable.
- CVE-2025-55188: symlink handling. Win9x has no symlinks, so not applicable.
- CVE-2023-40481 (SquashFS OOB write): the NVD CPE lists only 22.01; whether it affects 9.20 is unknown.
- CVE-2026-48112 (Ar handler, 9.18-26.00): 9.20 has DebHandler.cpp rather than a separate Ar handler; whether it is affected was not verified.
- Not affected per the NVD ranges: CVE-2026-48092 and -48103 (9.34+), CVE-2026-48101 and -48111 (UEFI, 9.21+), CVE-2024-11612 (24.06-24.07).

Summary: 13 CVEs apply, and 2 more may apply. The worst are CVE-2016-2334 (HFS+ heap overflow, CVSS2 9.3) and CVE-2026-48095 (NTFS heap overflow, CVSS3 8.8). Most need the user to open a crafted archive or disk image. The installer is also affected by DLL hijacking (CVE-2016-7804).

## Install behaviour

- Installer type: NSIS. The "Nullsoft" signature is in the exe, and the script DOC/7zip.nsi ships in the source.
- Silent install: documented in the 7-Zip FAQ (https://www.7-zip.org/faq.html): `7z920.exe /S /D=C:\Program Files\7-Zip`. The switches are case-sensitive. As standard NSIS, /D must be the last parameter and unquoted, although the FAQ shows it quoted.
- Default folder: `$PROGRAMFILES\7-Zip`, stored in HKLM and HKCU `Software\7-Zip\Path`.
- Uninstaller: yes. `$INSTDIR\Uninstall.exe` is registered at HKLM `Software\Microsoft\Windows\CurrentVersion\Uninstall\7-Zip` (DisplayName, UninstallString, NoModify, NoRepair). Uninstall with `Uninstall.exe /S` (standard NSIS).
- Side effects: registers the shell extension 7-zip.dll (`regsvr32 /s`) as context-menu and drag-drop handlers under HKCR, adds `Shell Extensions\Approved`, App Paths for 7zFM.exe, and Start Menu shortcuts. File associations are set by the user from 7zFM, not by the installer.
